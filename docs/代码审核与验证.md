## 主要修补

| 范围 | 当前实现与处理结果 |
| --- | --- |
| 登录与注册 | 移除 SecondMe OAuth 链路；通用邀请码注册时设置用户名与密码。旧回调转到本站登录页，邮箱验证码路由返回 410。 |
| 身份与权限 | 旧 `user_id` Cookie 不再有效。服务端校验随机会话、有效期与撤销状态；资料、项目更新、匹配和消息均校验当前用户归属。 |
| 注册竞争与密码 | 通用邀请码允许多个新账号使用；规范化用户名有唯一约束，用户与会话原子创建。密码使用随机盐和 scrypt 哈希，缺失账户也做同等密码计算；不存在明文密码存储。 |
| AI | 替换 Gemini 为服务端 DeepSeek；限制历史和请求大小，系统提示由服务端维护，结构化结果通过校验后才交给用户确认。超时、无 key、无效 JSON 或截断响应有明确反馈，不生成虚假匹配分数。 |
| 请求边界 | 写接口检查同源 Origin、会话、JSON 类型、实际请求字节数与字段格式；数据库限流可跨服务实例共享。内部错误不泄漏连接串、模型内容或堆栈。 |
| 数据访问 | 公开接口只展示发布记录；读取接口不再自动插入演示数据。业务表启用 RLS，并撤销 anon / authenticated 的 Data API 权限，业务访问统一经过服务端。 |
| 站内消息 | 用真实双人成员会话替换原型消息流程；明确发送后落库，仅会话双方可读写，重复请求 ID 不生成重复记录，可加载更早消息。 |
| 发布流程 | 直接编辑、AI 辅助和预览并列；保存草稿、确认发布、转为私密是明确操作。刷新可恢复标签页草稿，失败保留输入，AI 返回不覆盖请求期间的手工修改。 |
| 视觉与移动端 | 乳白底、深色文字、电蓝强调、几何图形与系统字体；重做首页、登录、编辑、探索、工作台与消息布局，手机端保留完整流程。 |
| 工程可靠性 | 恢复构建时的类型和 lint 检查，去掉构建中自动迁移数据库的行为，升级依赖并修补传递依赖告警；迁移和邀请码脚本可独立执行。 |

当前 `.secondme/state.json` 的旧 client secret 已清空。Git 历史仍可能保留它，需在 SecondMe 撤销旧凭据；没有自动改写提交历史或删除历史业务数据。

## 2026-10-24：恢复对话式档案梳理

用户反馈短回答触发“AI 返回的内容不完整”，并指出旧版能够理解模糊表达、主动整理档案。对照 `0c17738` 的项目 / 个人访谈提示，重新上线版本将主动归纳要求压缩成了保守提取，也缺少可点击建议的传递结构。原始失败响应未保存，无法断言截图对应哪一种输出错误。

- `src/lib/onboarding-ai.ts` 统一维护项目 / 个人访谈规则：理解口语、短句、指代与纠正，一次补充相关字段；每轮提供最多四个上下文相关的可选回答。
- 当前草稿与本轮表达放在同一条消息里；历史保留有序选项，因此“第二个”等回答仍有明确上下文。前端显示可点击选项，并随标签页草稿一起恢复。
- 浏览器实测发现旧聊天可能让模型覆盖手动修改。现在单独记录手动编辑的字段；模型修改它们时必须附本轮原文依据，服务端核对引用是否来自本轮。旧引用或无依据的覆盖被跳过，其他正常归纳继续处理。这是来源检查，不是对模型语义正确性的保证。
- 未提供的字段和 null 不清空已有档案；字符串形式的技能列表会规范为数组。JSON / 字段格式错误或截断最多重试一次，两次调用共享 45 秒截止时间。诊断日志只保留错误类别和字段名，不记录对话、档案值或密钥。
- 点击建议时保留未发送的输入；回复返回时保留等待期间新写的文字，以及手动改过的草稿字段。仅追问、没有字段更新时不再提示“已填入草稿”。

## 2026-10-25：多选对话、用户库与项目关联

- 建议回答改为可多选、再次点击取消，选好后统一发送。选中的内容与自由补充合并成同一轮消息；不会因为点选立即请求模型。失败保留选择和文字，重试不丢内容；新问题不继承上一轮的勾选。
- DeepSeek 提示支持组合选择、“第一和第三个”等复数指代，并保留补充条件。手机实测发现模型引用列表时可能省略项目符号、折叠换行，导致手工字段来源检查误拒绝；现在只规范这些排版差异，保留文字、否定词、标点与数值符号。历史内容仍不能覆盖手工字段。
- 工作台首屏并列展示个人档案与项目，编辑页提供直接切换。当前标签页记住最近的项目入口，先建立项目后可以完善个人档案，再继续原项目草稿；项目 ID 不变，不重复创建。普通登录返回工作台，从公开详情登录后返回原详情。
- 主导航增加“发现伙伴”。用户库支持关键词与城市筛选，公开个人页展示技能、经历、合作方向，以及该用户发起的公开项目。
